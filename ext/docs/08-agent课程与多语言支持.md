## 二、两门 agent 课

### 2.1 来历

参照 `earendil-works/pi`（MIT，TypeScript）的实际结构，按渐进路径重排成二十章。
不是把 pi 的三万行翻译一遍——那里面大部分代码在处理各家模型供应商的差异，
对理解原理没有帮助。目标是「读完这门课，再去看 pi 的源码能看懂」。

pi 的设计和课程章节几乎一一对应，可以做「真实实现对照」：

| pi 里的东西 | 对应本课 |
|---|---|
| `pi-ai` 的内容块（text / thinking / toolCall）与 `toolResult` 角色 | 第 2 章 |
| `StreamEvent` 与「不保证连续、要用 `contentIndex` 归位」 | 第 7 章的累加器 |
| `AgentTool` 的 `execute(toolCallId, params, signal, onUpdate)` | 第 9 章 |
| `agentLoop` 与 `executionMode: "sequential"` | 第 10、11 章 |
| `AgentState` / `Agent` | 第 13 章 |
| `SessionManager`、`~/.pi/agent/sessions/`、`id`/`parentId` 成树 | 第 14、15 章 |
| `compaction_start` 事件 | 第 16 章 |
| `.pi/skills/`、`.agents/skills/` | 第 19 章 |

### 2.2 五个部分

| 部分 | 章 | 解决什么 |
|---|---|---|
| 一、骨架与协议 | 1-5 | 消息与内容块、事件流、消息存储、脚本化的假模型 |
| 二、接上真模型 | 6-8 | 供应商适配、流式解析、换真模型而调用方一行不改 |
| 三、agent 的心脏 | 9-12 | 工具契约、主循环、并发与取消、模型不听话怎么办 |
| 四、记忆 | 13-16 | 有状态的 agent、会话持久化、会话树、上下文压缩 |
| 五、干活的 agent | 17-20 | 编码工具、权限与沙箱、技能、评估 |

### 2.3 贯穿全书的判断

这些是课程真正要传递的东西，不是 API 用法：

- **先定接口，再写实现。** 前七章一次都不真的调用模型，用剧本模型逼自己
  定义一个「你自己想要的」接口。第 8 章换上真模型时，调用方一个字不用改。
- **每个工具调用都必须有对应的结果。** 取消、分叉、压缩全都受这条约束。
  少一条，这段对话会被服务端永久拒绝。
- **必须有循环预算。** 模型陷入循环时不报错、不崩溃，只是永远不结束。
- **能用机制解决的，不要靠提示词解决。**
- **提示词不是安全边界。**
- **覆盖文件前必须先读过**——防的不是恶意，是模型的自信。
- 压缩的单位是**轮**，不是消息。
- 没有评估集，改提示词就是玄学。

### 2.4 课程形态的三次调整

初版 90% 是代码、零张图，从第 8 章起每章代码占比 ≥90%，单格最大 223 行。
根因有两个，分开处理：

**一、「本章起点」是纯机械开销。** 一页一个新内核，所以每章开头要把前面
所有章的代码再贴一遍。实测这一格占了全课代码量的 41%。
解法是给两种语言各配一条通道（第三节）。

**二、讲解本身太薄。** 每章约 1400 字符正文。这一条改了三轮：

| 轮次 | 做法 | 结果 |
|---|---|---|
| 加图 | mermaid 图 + 提示框 + 自测题 | 代码占比 93% → 69% |
| 加理论 | ReAct/function calling/MCP 的来路、workflow 与 agent 的判据、pi 的切法 | 讲解 2166 → 7225 字符 |
| **按 HF 密度重排** | 量了 HuggingFace LLM 课程一节：**28 个代码块**、段落与代码块之比 3:1 | 代码块 2 → 19 个，讲解 → 11769 字符 |

最后一轮是关键：**差别在结构不在字数**。原来是「一篇长文加两段大代码」，
读起来像博客；HF 那一页是「两三句话说清要做什么 → 一小段代码 →
一两句输出 → 几句解读」持续交替。

### 2.5 当前状态

| | Python 版 | Go 版 |
|---|---|---|
| 章节数 | 20 | 20 |
| 第 1 章 | **新形态**（65 块：讲解 37 / 代码 19 / 提示框 6 / 图 2 / 自测 1） | 中间形态（18 块） |
| 第 10 章 | 中间形态 | 中间形态 |

体量，超出单次会话的产出量。机制、模子、指南都已就位，内容可以按
《课程编写指南》逐章补。

## 三、课程模块加了什么

### 3.1 三类新的内容块

书引擎本来就有这些块类型，导入器之前只产 `text` 和 `code`：

| 讲义里写 | 变成 | 组件读的字段 |
|---|---|---|
| ` ```mermaid ` / `svg` / `chartjs` | `figure`（浏览器里画图） | `code.{language,content}` / `render_type` / `description` |
| `> [!要点]` / `[!坑]` / `[!小结]` / `[!提示]` | `callout`（四色提示框） | `variant` / `label` / `body` |
| ` ```quiz `（YAML） | `quiz`（选择题，可作答可看解析） | `questions` |

片段的种类因此从两种（code / text）扩到四种（+ figure / quiz / callout）——
之前非代码围栏一律归 text，图被当成讲解文字。

### 3.2 两条「累积代码」通道

让讲义不必每章重贴两百行：

**Python**：内核切工作目录时，把 cwd 及上溯三层加进 `sys.path`。
课程可以自带一个包（`chapters/zh/agentlib/`），讲义里写一行
`from agentlib import *`。

**Go**：累积编译前先铺本部分目录下的 `_prelude/*.go`。同名以页面里的格子为准，
学生想覆盖某个铺底文件写一个同名格子就行。没有这个目录的旧讲义照跑不误。

### 3.3 五种语言可运行

| 围栏 | 执行模型 | 变量跨格子 |
|---|---|---|
| `python` | 一页一个长驻 Jupyter 内核 | 能 |
| `go` | 多文件累积编译（`// file:` 定文件名） | 靠同包顶层声明 |
| `javascript` / `typescript` | 到当前格为止拼成一个脚本交给 node | 能 |
| `rust` | 到当前格为止拼成一个 `main.rs`，前面各格的 `fn main` 被摘掉 | 靠顶层定义 |

TypeScript 用 Node 自带的类型剥离（`--experimental-strip-types`），
只剥类型不做类型检查——省掉一个几十兆的依赖和一次编译等待。

**JS 拼接的代价**：同一个作用域，两格里不能都写 `const x`，会报重复声明。
这一点和 Python 不同，已写进编写指南。

### 3.4 工具链装在哪，以及一个网络坑

三套工具链都在内核镜像里。**Go 和 Node 的安装包放在
`kernel-image/vendor/`，构建时只做拷贝**，原因是：

这台机器通过 Tailscale 的出口访问 `dl.google.com`、`nodejs.org`，
宿主上 curl 得到，但**容器网络到不了那条链路**——它把域名解析到
`198.19.x` 的 Tailscale 地址却没有对应路由，表现是 `SSL_ERROR_SYSCALL`。
在宿主上下载好再拷贝，绕开这件事。

Rust 走系统源（apt 能通），版本 1.75。换 rustup 需要构建时联网，做不到。

**顺带修了一个定时炸弹**：Go 本来只存在于已经跑起来的那个镜像里，
`Dockerfile` 里没有装它的步骤——谁重建一次镜像，Go 课就全废了。现在补进去了。

`vendor/` 不进 git（几十兆二进制），换机器部署要重新下载，命令写在
Dockerfile 的注释里。

## 四、交互上的改动

### 4.1 问助教：从预填改成引用卡片

第一版把整格代码拼成一段话塞进输入框。实测三个问题：

- 输入框是 `rows={1}`（32 像素高），却被塞进 425 字符 / 14 行；
- 学生自己要写的问题挤在看不全的一堆代码后面；
- 面板上没有等待提示，而这条链路**首字实测 28 秒**。

改成：代码变成输入框上方一张可展开、可移除的引用卡片；输入框留空；
发给模型时才把引用拼进去，聊天记录里只显示「问题 +（附：第 N 格代码）」；
输入框随内容增高。

### 4.2 问答面板显示思考步骤

主界面用的 `AssistantActivity` 组件直接接上。发问 10 秒时显示
「正在调查你的上下文 · 10s」，展开可见「上下文调查」「读取来源 bk-…」。

接上之后暴露两处必须一起修的缺陷：

- **本轮刚建的会话会把正在流式输出的消息清掉。** 第一次提问时后端才创建会话，
  父组件回填 id，面板那个「换会话就重置」的副作用在回答进行到一半时触发。
  判据收窄成「书页或会话真的换了才重置」。
- **用户气泡被引用的代码撑满。** 改成显示层折叠，不改存下来的内容。

### 4.3 那 28 秒是怎么来的

同样上下文直连模型只要 4.8 秒。差的 24 秒是 DeepTutor 自身问答流水线：
页面内容不是直接塞进提示词，而是进「Attached Sources」清单，**只给 2000 字符预览**，
模型要看全文得自己调 `read_source`。这一步在回答之前跑，是一个独立的
探查前置流程（最多 5 轮）。所以是两段 LLM 调用。这是上游设计，不是我们引入的。

### 4.4 「重建书籍」按钮

上游的这个按钮会**删掉全部页面，让模型按大纲重新生成**。对 DeepTutor 自己
生成的书这是对的，对导入的课程是毁灭性的——页面是人写的讲义。
确认框写的是「Existing generated pages will be replaced」，看不出区别。

**已经误伤一次**：Python 课 20 页被删到 6 页，首页变成模型生成的「本书导览」，
从原稿恢复了。

现在课程书上按钮文字改成「从原稿重新导入」，点下去调课程导入接口。
普通书行为未变。为此给书的 metadata 补了 `course_origin`——之前只记了
`course_root`（`data/user/courses` 下的副本），读它等于没改。

## 五、修过的缺陷

| # | 症状 | 根因 | 教训 |
|---|---|---|---|
| 1 | 连跑二十多页时偶发「连不上内核」 | 内核池上限 12，一次扫过 40 页不停回收再新建；创建内核的 HTTP 请求卡在 30 秒 | 执行失败自动重来一次（**取内核也要包进重试**，第一版漏了这个，日志里一条重试记录都没有才发现）；超时提到 90 秒 |
| 2 | Go 讲义后几格编译失败 | 常量写在 `main.go` 里，被后面格子的 `main.go` 覆盖 | 跨格子的东西放不会被覆盖的文件；已写进讲义注释和指南 |
| 3 | 提示框渲染成空框 | 组件读 `variant`/`label`/`body`，我写的 `markdown`/`text` | ↓ |
| 4 | 自测题变成开放题、选项白写 | 题型写了 `single_choice`，不在前端别名表里 | ↓ |
| 5 | **整页正文空白**，但大纲里块都在 | `TextBlock` 只读 `payload.body`，我写的 `markdown`/`text` | **同一类错的第三次**。根因是按直觉命名 payload 字段，没逐个对照组件读什么 |
| 6 | 生成的 JS 什么都不输出、Rust 语法错误 | 生成执行代码时多做了一层 JSON 编码，写进文件的是**加引号的字符串字面量** | JS 把它当成一个字符串表达式，合法但什么都不做——「跑通了」不等于「跑对了」 |

### 第 5 条的教训值得单独写

那三次都是同一个模式：**我按自己的直觉命名 payload 字段，没有对照组件读什么。**
后果一次比一次严重，最后一次导致两门课 40 页的讲解文字**从来没显示过**——
而我在此期间还在不停地往里加字，加的字一个都没显示出来，
却拿导入统计里的块数当验收通过了。

**验收方式因此改了**：新增块类型必须实际读一遍浏览器里渲染出来的页面文字，
不能只看块数。五种块的字段对照表记在编写指南的第九节。

## 六、《课程编写指南》

`courses/编写指南.md`，面向写课的人。十节加一个附录：

五分钟做出第一门课 / 六种内容块的写法与坑 / 代码格的运行模型 /
课程大了之后怎么让前面的代码接着用 / 一章该怎么组织（含密度参考与实证依据）/
改完怎么生效 / 怎么验证 / 怎么打包分发 / 疑难排查表 / 可照抄的模板 /
附录：五种语言的代码格。

写完照着第一节自己走了一遍：建三个文件、导入、六种块逐一核对显示、
两个代码格真跑。

### 一章该怎么组织（第五节摘要）

依据来自 Crafting Interpreters 等教程的实际结构，以及几条教学实证：

- **代码约在全章三分之一处才第一次出现**，前面是散文讲问题与设计权衡。
- **背景知识随用随讲**，不集中开预备章。
- **图上直接标注**，不要写「详见下图」——空间邻近原则效应量最大（d=1.10），
  而「详见下图」这种写法本身就是违规信号。
- **讲机制优先用静态图加标注**，动态演示转瞬即逝、难以对比细节。
- **先预测再运行**，有两条独立实证（PRIMM 准实验 p=.001；随机对照 d=0.36）。
- **章末必须有自测题**，提取练习是学习技巧综述里仅有的两个「高效用」之一。

密度参考（量自 HuggingFace LLM 课程）：一章 20-30 个代码块，
**大多数 6-15 行**，段落与代码块之比约 3:1，文字占 60% 以上。
