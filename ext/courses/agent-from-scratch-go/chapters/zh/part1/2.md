# 消息与内容块

上一章的消息长这样：

```go
type Msg struct {
	Role    string
	Content string
}
```

`Content` 是个字符串。这在只有纯文本时够用，但助手的一条回复里**可能同时有文字和
若干个工具调用**——

> 「我先查一下时间。」+ `get_time(city="北京")` + `get_weather(city="北京")`

一个字符串装不下这三样东西。所以真实的 agent 框架都把内容做成**一个块列表**，
每块有自己的类型。pi 是这么做的，Anthropic 和 OpenAI 的接口也都是这么做的。

## 三种块就够了

| 块类型 | 谁产生 | 装什么 |
|---|---|---|
| `text` | 用户或模型 | 一段文字 |
| `tool_use` | 模型 | 「我要调这个工具，参数是这些」，带一个调用编号 |
| `tool_result` | 我们的代码 | 工具执行完的结果，用调用编号对上是哪一次调用 |

**调用编号是关键。** 一轮里模型可能同时要求调三个工具，结果回填时必须能对上是哪个结果
配哪个调用。

## Go 里怎么表达「一个值可能是三种类型之一」

Python 那边用的是联合类型加 `isinstance` 判断。Go 没有联合类型，常见的做法有两种：

| 做法 | 好处 | 代价 |
|---|---|---|
| **接口 + 类型断言** | 各块的字段互不干扰，编译器帮你检查 | 序列化时要自己处理类型信息 |
| **一个结构体，字段全放一起** | 序列化直接可用 | 字段是无效的组合也编译得过（文字块带着工具参数） |

我们用**接口**，因为这门课后面要反复对块做判断，接口配类型断言读起来更清楚。
序列化那点麻烦在本章末尾一次性解决。

```go
// file: blocks.go
package main

import (
	"crypto/rand"
	"encoding/hex"
	"fmt"
)

func newID(prefix string) string {
	buf := make([]byte, 6)
	rand.Read(buf)
	return prefix + "_" + hex.EncodeToString(buf)
}

// Block 是消息内容的一个片段。BlockType 让我们在不做类型断言时也能知道它是什么。
type Block interface {
	BlockType() string
}

// TextBlock 一段文字。
type TextBlock struct {
	Text string `json:"text"`
}

func (TextBlock) BlockType() string { return "text" }

// ToolUseBlock 模型要求调用一个工具。ID 是这次调用的编号，结果靠它对上。
type ToolUseBlock struct {
	ID   string         `json:"id"`
	Name string         `json:"name"`
	Args map[string]any `json:"args"`
}

func (ToolUseBlock) BlockType() string { return "tool_use" }

// ToolResultBlock 一次工具调用的结果。
type ToolResultBlock struct {
	ToolUseID string `json:"tool_use_id"`
	Content   string `json:"content"`
	IsError   bool   `json:"is_error"`
}

func (ToolResultBlock) BlockType() string { return "tool_result" }

// Message 一条消息：角色 + 若干内容块。
type Message struct {
	ID      string
	Role    string // system / user / assistant / tool
	Content []Block
}

// Text 把这条消息里所有文字块拼起来。日志和展示常要用。
func (m Message) Text() string {
	out := ""
	for _, b := range m.Content {
		if t, ok := b.(TextBlock); ok {
			out += t.Text
		}
	}
	return out
}

// ToolUses 取出这条消息里的所有工具调用。
func (m Message) ToolUses() []ToolUseBlock {
	var calls []ToolUseBlock
	for _, b := range m.Content {
		if c, ok := b.(ToolUseBlock); ok {
			calls = append(calls, c)
		}
	}
	return calls
}

func NewMessage(role string, blocks ...Block) Message {
	return Message{ID: newID("msg"), Role: role, Content: blocks}
}

func NewToolUse(name string, args map[string]any) ToolUseBlock {
	return ToolUseBlock{ID: newID("call"), Name: name, Args: args}
}

var _ = fmt.Sprintf // 这一格还没用到 fmt 的其他函数，先占个位
```

## 用它表示上一章那轮对话

```go
// file: main.go
package main

import "fmt"

func main() {
	// 模型的回复：一句话 + 一个工具调用，两个块并存在同一条消息里
	call := NewToolUse("get_time", map[string]any{"city": "北京"})

	history := []Message{
		NewMessage("user", TextBlock{Text: "北京现在几点？"}),
		NewMessage("assistant", TextBlock{Text: "我查一下。"}, call),
		NewMessage("tool", ToolResultBlock{ToolUseID: call.ID, Content: "14:32"}),
		NewMessage("assistant", TextBlock{Text: "北京现在是 14:32。"}),
	}

	for _, m := range history {
		kinds := ""
		for i, b := range m.Content {
			if i > 0 {
				kinds += "、"
			}
			kinds += b.BlockType()
		}
		text := m.Text()
		if text == "" {
			text = "（无）"
		}
		fmt.Printf("%-10s 块：%-24s 文字：%s\n", m.Role, kinds, text)
	}
}
```

跑出来能看到，第二条消息里 `text` 和 `tool_use` 两种块**并存**——这正是上一章那个
字符串装不下的东西。

## 序列化：接口带来的那点麻烦

Go 的 `encoding/json` 不知道一个 `Block` 接口值背后是什么类型，读回来时也不知道该
构造哪个结构体。解决办法是**在外层包一个带类型标记的信封**：

```go
// file: codec.go
package main

import (
	"encoding/json"
	"fmt"
)

// blockEnvelope 是块在 JSON 里的样子：一个类型标记 + 原始数据。
type blockEnvelope struct {
	Type string          `json:"type"`
	Data json.RawMessage `json:"data"`
}

type messageEnvelope struct {
	ID      string          `json:"id"`
	Role    string          `json:"role"`
	Content []blockEnvelope `json:"content"`
}

func encodeMessage(m Message) ([]byte, error) {
	env := messageEnvelope{ID: m.ID, Role: m.Role}
	for _, b := range m.Content {
		data, err := json.Marshal(b)
		if err != nil {
			return nil, fmt.Errorf("块 %s 序列化失败：%w", b.BlockType(), err)
		}
		env.Content = append(env.Content, blockEnvelope{Type: b.BlockType(), Data: data})
	}
	return json.Marshal(env)
}

func decodeMessage(raw []byte) (Message, error) {
	var env messageEnvelope
	if err := json.Unmarshal(raw, &env); err != nil {
		return Message{}, fmt.Errorf("消息读不出来：%w", err)
	}
	m := Message{ID: env.ID, Role: env.Role}
	for _, item := range env.Content {
		var b Block
		switch item.Type {
		case "text":
			var v TextBlock
			if err := json.Unmarshal(item.Data, &v); err != nil {
				return Message{}, err
			}
			b = v
		case "tool_use":
			var v ToolUseBlock
			if err := json.Unmarshal(item.Data, &v); err != nil {
				return Message{}, err
			}
			b = v
		case "tool_result":
			var v ToolResultBlock
			if err := json.Unmarshal(item.Data, &v); err != nil {
				return Message{}, err
			}
			b = v
		default:
			// 遇到不认识的块类型就跳过，而不是让整条消息读不出来。
			// 存储格式会演进，旧代码读新数据是常态。
			continue
		}
		m.Content = append(m.Content, b)
	}
	return m, nil
}
```

改一下 `main.go`，把往返验一遍：

```go
// file: main.go
package main

import (
	"encoding/json"
	"fmt"
)

func main() {
	call := NewToolUse("get_time", map[string]any{"city": "北京"})
	original := NewMessage("assistant", TextBlock{Text: "我查一下。"}, call)

	raw, err := encodeMessage(original)
	if err != nil {
		fmt.Println("序列化失败：", err)
		return
	}

	var pretty map[string]any
	json.Unmarshal(raw, &pretty)
	indented, _ := json.MarshalIndent(pretty, "", "  ")
	fmt.Println(string(indented))

	restored, err := decodeMessage(raw)
	if err != nil {
		fmt.Println("反序列化失败：", err)
		return
	}
	fmt.Printf("\n往返之后：角色 %s，块 %d 个，文字 %q，工具调用 %d 个\n",
		restored.Role, len(restored.Content), restored.Text(), len(restored.ToolUses()))
	fmt.Println("工具调用编号对得上：", restored.ToolUses()[0].ID == call.ID)
}
```

## 为什么不用字符串拼

有人会想：直接把工具调用写成 `"[调用 get_time(city=北京)]"` 塞进字符串不行吗？

不行，三个原因：

1. **要能精确对上。** 一轮三个工具调用，结果回填时靠编号配对，字符串里没有编号。
2. **要能发给模型。** 模型接口要的就是结构化的工具调用字段，你最终还得解析回来。
3. **要能被程序检查。** 「这一轮模型调了哪些工具」这种问题，遍历块是几行代码，
   解析字符串是一堆正则。

## 本章小结

- 消息的内容是**一个块列表**，不是字符串。
- 三种块够用：文字、工具调用、工具结果。
- **工具调用要带编号**，结果靠编号对上。
- Go 里用**接口加类型断言**表达「三选一」，序列化时套一个带类型标记的信封。
- 反序列化**遇到不认识的类型要跳过**而不是报错，因为存储格式会演进。

Go 这边用的是通道。
