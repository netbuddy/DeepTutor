# 课程编写指南

这份文档告诉你怎么从零做一门课，以及怎么修订已有的课。读完你能独立完成
「写讲义 → 导入 → 验证 → 打包发给别人」这一整条路。

面向的是**写课的人**，不是读课的人。

---

## 一、五分钟做出第一门课

先做一门只有一课的课，把链路跑通，再往上加内容。

### 1.1 建目录

```
~/DeepTutor-ext/courses/我的第一门课/
├── README.md
└── chapters/
    └── zh/
        ├── _toctree.yml
        └── part1/
            └── 1.md
```

三个文件缺一不可。`README.md` 是课本首页，`_toctree.yml` 是目录，
`part1/1.md` 是第一课。

### 1.2 写 README.md

它会成为书的首页。随便写，Markdown 正常渲染：

```markdown
# 我的第一门课

一句话说明这门课讲什么、读完能做到什么。
```

### 1.3 写 _toctree.yml

```yaml
- title: 第一部分 · 入门
  sections:
  - local: part1/1
    title: 第一课的标题
```

三条规矩：

- `local` 是**相对 `chapters/zh/` 的路径，不带 `.md` 后缀**。
  写 `part1/1` 对应文件 `chapters/zh/part1/1.md`。
- `title` 是显示在侧栏和页面顶部的标题，和文件里的一级标题可以不同。
- 顶层每一项是「一个部分」，`sections` 下面每一项是「一课」，也就是一页。

### 1.4 写第一课

```markdown
# 第一课的标题

这里是讲解文字，Markdown 正常渲染：**加粗**、`行内代码`、表格、列表都行。

    ```python
    print("这一格可以点运行")
    ```
```

（上面示例里的围栏多缩进了四格，是为了在本文档里展示。真写的时候顶格写。）

### 1.5 导入

在课程管理页（侧栏「课程」）填目录路径，或者用命令行：

```bash
curl -s -X POST http://127.0.0.1:9188/api/v1/ext/course/create \
  -H 'Content-Type: application/json' \
  -d '{"origin": "/home/yun/DeepTutor-ext/courses/我的第一门课",
       "slug": "my-first-course",
       "title": "我的第一门课",
       "replace": true}'
```

- `origin`：课程目录的绝对路径（也可以是 Git 仓库地址）。
- `slug`：这门课的短标识，只能用字母数字和连字符。同一个 slug 重复导入是覆盖。
- `replace: true`：允许覆盖。不写的话第二次导入会报「已经存在」。

导入成功后去「书籍」页就能看到它。

## 二、六种内容块怎么写

一课的 md 文件会被切成若干**块**。写法和坑如下。

### 2.1 讲解块

围栏之外的一切都是讲解块。Markdown 正常渲染，支持标题、表格、列表、
引用、行内代码、链接、数学公式。

**切分规则**：按二级标题（`##`）切。一个 `##` 到下一个 `##` 之间的内容是一个块，
块的标题就是那行 `##` 的文字，会出现在页面右侧的「本页内容」大纲里。

**所以小标题要好好写**——它是读者在大纲里唯一看到的东西。两条建议：

- 标题里不要用 `**加粗**`，大纲里会把星号原样显示出来。
- 标题写成一句能读懂的话，不要写「其二」「补充说明」这种。

### 2.2 可运行的代码格

用带语言标记的围栏，目前只有 `python` 和 `go` 可运行：

    ```python
    print("hello")
    ```

它会渲染成一个带四个按钮的代码格：**运行 / 从头跑到这 / 重置 / 问助教**。
学生可以直接在里面改代码再跑。

其他语言（`js`、`sql`、`bash`……）也能写，但只做语法高亮，**没有运行按钮**。

### 2.3 图

用 `mermaid`、`svg` 或 `chartjs` 围栏。浏览器里直接画，不出网、不需要图片文件：

    ```mermaid
    flowchart LR
        A[用户提问] --> B[模型]
        B --> C[回答]
    ```

图会带「全屏 / 显示代码 / 复制代码」三个按钮。

**坑一**：`timeline` 图**不认 `<br/>`**，标签要写成一行。
`flowchart` 和 `sequenceDiagram` 里可以用 `<br/>` 换行。

**坑二**：节点文字里有中英文标点混排时，用引号包起来更稳：
`A["用户提问（第一步）"]`。

### 2.4 提示框

用 GitHub 风格的告警语法，四种：

```markdown
> [!要点]
> 这一章最要紧的一句话。

> [!坑]
> 一个容易踩的错误。

> [!小结]
> 收束性的总结。

> [!提示]
> 补充说明，跳过不影响主线。
```

四种分别是琥珀色灯泡、玫瑰色警告、天蓝色书签、翠绿色闪光。

**坑**：提示框的正文是**按纯文本渲染的**，写 `**加粗**` 会把星号原样显示出来。
框里只写朴素的句子。

### 2.5 自测题

用 `quiz` 围栏，里面是 YAML，一题一项：

    ```quiz
    - 题目: 这里问一个问题？
      选项:
        A: 第一个选项
        B: 第二个选项
        C: 第三个选项
      答案: B
      解析: 为什么选 B。这段话在学生点「显示答案」之后出现。

    - 题目: 第二题可以接着写。
      选项:
        A: 是
        B: 否
      答案: A
      解析: 解释。
    ```

不写 `选项` 就变成开放题，学生只能点开看参考答案。

**坑**：YAML 对缩进敏感。`选项` 下面的每一项要缩进两格，
题目里如果有冒号，整句要用引号包起来：`题目: "为什么 a: b 会报错？"`。

### 2.6 表格、公式、其他

表格、行内公式（`$...$`）、块级公式（`$$...$$`）都能正常渲染，
写在讲解块里就行。

## 三、代码格是怎么跑起来的

这一节解释运行模型，不理解它写出来的课会时不时出怪事。

### 3.1 Python：一页一个长驻内核

**同一页里的代码格共享一个 Python 进程。** 第 1 格定义的变量，第 5 格能直接用。
这和 Jupyter notebook 的体验一样。

**换一页就是全新的进程。** 第 2 章拿不到第 1 章定义的任何东西。

三个按钮的区别：

| 按钮 | 做什么 |
|---|---|
| 运行 | 只跑这一格 |
| 从头跑到这 | 从本页第一格依次跑到这一格，适合中途进来的读者 |
| 重置 | 丢掉这一页的内核，下次运行从干净环境开始 |

**代码不写进任何 .ipynb 文件。** 「一格一格跑、变量能接着用」这个体验来自
共享的 Jupyter 内核，不来自 notebook 文件格式。

### 3.2 Go：累积编译

Go 是编译型语言，没有长驻内核。这里用的是**累积编译**：

- 每一格的开头写 `// file: xxx.go`，决定这一格写进哪个文件；
- 点运行时，把本页**到这一格为止**的所有文件凑齐，一起编译；
- 同名文件后写的覆盖先写的。

因此有两条 Go 专属的约束，写讲义时必须守住：

- **跨格子要用的东西不要写在 `main.go` 里。** 后面每一格通常都有自己的 `main`，
  写在 `main.go` 里的常量下一格就不存在了。
- **每一格都要能独立编译。** 不能引用后面格子才定义的函数。

没有 `main` 函数的格子只做编译检查（`go vet`），有 `main` 的会真的跑起来。

### 3.3 代码能读到哪些文件

代码格的工作目录是**这一课所在的目录**（`chapters/zh/part1/` 之类）。
课程目录被只读挂载进执行容器，所以：

- 课程里自带的数据文件、模板文件，用相对路径能读到；
- **写文件要写到 `/tmp` 下**，课程目录是只读的。

## 四、课程大了之后：让前面的代码接着用

一门课写到第十章，每章开头都要把前面的代码重贴一遍——这是最常见的失控点。
两种语言各有一条通道。

### 4.1 Python：课程自带一个包

在 `chapters/zh/` 下放一个包：

```
chapters/zh/
├── _toctree.yml
├── agentlib/            ← 随便叫什么名字
│   ├── __init__.py
│   ├── blocks.py
│   └── tools.py
└── part3/
    └── 10.md
```

讲义里一行就够：

```python
from agentlib import *
```

**原理**：内核切工作目录时，会把当前目录及其上溯三层加进 `sys.path`。
工作目录是 `chapters/zh/part3`，所以 `chapters/zh/` 下的包能被找到。
放在课程根目录也行。

### 4.2 Go：每部分放一个铺底目录

在这一部分的目录下建 `_prelude/`：

```
chapters/zh/part3/
├── _prelude/
│   ├── core.go
│   └── tools.go
├── 10.md
└── 11.md
```

累积编译时，`_prelude/*.go` 会**先**被铺进编译目录，然后才叠上本页各格。
同名以页面里的格子为准——学生想覆盖某个铺底文件，写一个同名的格子就行。

没有这个目录的课程照跑不误。

### 4.3 一条写作建议

库里的代码应该是**读者自己在前面章节逐格写出来的东西，一行不改**，
只是收进了文件。不要在库里塞讲义里没出现过的实现——读者会在某一章突然
用到一个他没见过的函数，那比重贴两百行更糟。

## 五、一章该怎么组织

这一节是写作建议，不是技术要求。依据来自几本公认写得好的教程和一些教学实证。

### 5.1 推荐的顺序

| 位置 | 写什么 |
|---|---|
| 开头 | **一个具体的问题**，不是定义。让读者先感到痛 |
| 接着 | 这个问题为什么存在、不解决会怎样 |
| 代码出现前 | **先让读者预测**：「运行之前，先想想会输出什么」 |
| 中段 | 讲解与小代码格**持续交替**，一格只演示一件事 |
| 每格之后 | 一两句说输出是什么，两到四句解释它说明了什么 |
| 章末 | 小结 → 练习 → 自测题 |
| 可选 | 「设计笔记」：讨论取舍，明说可以跳过 |

### 5.2 密度参考

拿 HuggingFace 的 LLM 课程一节量的数字，可以当基准：

| 指标 | 参考值 |
|---|---|
| 代码块数量 | 一章 20 到 30 个 |
| 单个代码块行数 | **大多数 6 到 15 行**，超过 35 行的不超过三个 |
| 段落与代码块之比 | 约 3:1 |
| 文字占全章篇幅 | 60% 以上 |
| 提示框 | 一章 5 到 7 个 |
| 练习 | 一章 3 到 4 道 |

**最容易犯的错是「一篇长文加两段大代码」。** 那读起来像博客，不像教程。
正确的节奏是：两三句话说清要做什么 → 一小段代码 → 一两句输出 → 几句解读 →
接着下一个问题。

### 5.3 几条有实证支持的做法

- **先预测再运行**。在代码格前面写三个问题让读者先答，代码后逐个对答案。
  有随机对照实验支持这比直接讲解学得更好。
- **图上直接标注**，不要写「详见下图」。文字和它解释的图形要挨在一起，
  这条在多媒体学习的实证里效应量最大。
- **讲机制优先用静态图加标注**，而不是让读者跑代码看动态过程——
  动态过程转瞬即逝，难以对比细节。
- **图要选对类型**：多个角色按时间交互用时序图；一个对象在哪些状态间切换
  用状态机图；任务的执行路径用流程图。三者不能混用。
- **章末必须有自测题**。提取练习是学习技巧综述里评级最高的两种之一。

## 六、改完怎么生效

**权威原稿只有一份**：`~/DeepTutor-ext/courses/<课程名>/`。它进 git。

改完之后，两条路二选一：

- **在书的侧栏点「从原稿重新导入」**（推荐）。按钮会按原稿重新读一遍。
- 跑一遍第 1.5 节那条 `curl`。

> [!坑]
> 书的侧栏上，普通书显示的是「重建书籍」——那个按钮会**删掉全部页面，
> 让模型按大纲重新生成**。导入的课程上它已经被换成「从原稿重新导入」，
> 但如果你在别的书上看到「重建书籍」，别乱点。

导入会把课程目录复制进 `data/user/courses/`。这一步不能省：执行容器只挂了
那一个目录（只读），课程放在别处它看不见，代码格就跑不起来。
**那份副本是派生物，永远改原稿。**

浏览器里已经打开的阅读页不会自动刷新，按 F5 重新加载。

## 七、验证：逐段真跑一遍

导入成功不等于代码能跑。有一个脚本会把每一页的每个代码格真的执行一次：

```bash
~/DeepTutor-src/.venv/bin/python ~/DeepTutor-ext/bin/verify-course.py
```

它会输出每一格的通过与否、耗时、第一行输出。**新写完一章一定要跑一遍。**

> [!要点]
> 光看导入统计里的块数**不算验证**。块数对不代表内容显示得出来——
> 曾经有一次所有讲解块都存在、大纲里都看得见，但页面上一片空白，
> 因为 payload 的字段名写错了。验证要实际打开页面读一遍。

Go 的编译错误会写到标准错误里而不体现在内核状态上，验证脚本对此有专门判断。

## 八、打包发给别人

```bash
curl -s -o 我的课.dtcourse \
  http://127.0.0.1:9188/api/v1/ext/course/<slug>/export
```

包是一个 gzip 压缩的 tar，里面只有 `package.json`、`README.md` 和 `course/` 原稿——
**不含课本和检索索引**，因为那两样带着本机的绝对路径。导入时会在本机重新生成。

别人导入：

```bash
curl -s -X POST http://127.0.0.1:9188/api/v1/ext/course/import-package \
  -F 'file=@我的课.dtcourse' \
  -F 'replace=true'
```

或者在课程管理页上传。

## 九、疑难排查

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 页面一片空白，但右侧大纲里块都在 | 讲解块的 payload 字段名不对 | 这是导入器的 bug，已修；如果自建块类型要注意组件读哪个字段 |
| 提示框显示出来但里面没字 | 同上，callout 读的是 `body` | 检查导入器 |
| 自测题变成「开放题」，选项没显示 | 题型字符串不在前端别名表里 | 用 `choice` |
| mermaid 图里出现字面的 `<br/>` | `timeline` 不支持 `<br/>` | 标签写成一行 |
| 大纲里的标题带着 `**` | 小标题里用了 Markdown 强调 | 标题里别用 `**` |
| 改了原稿页面没变 | 浏览器缓存了页面 | F5；或确认点的是「从原稿重新导入」 |
| Go 代码报 `undefined: XXX` | 引用了后面格子才定义的东西，或写在了被覆盖的 `main.go` 里 | 见 3.2 两条约束 |
| Python 代码报 `NameError` | 换页了，内核是新的 | 在本页开头把需要的东西导入或定义 |
| 首次运行报「连不上内核」 | 内核冷启动 | 已有自动重试；仍失败就点「重置」 |
| 课程导入报「已经存在」 | 没传 `replace` | 加 `"replace": true` |

## 十、一份可以照抄的模板

```markdown
# 这一章的标题

## 从一个具体的问题说起

（两三段话，让读者感到痛。不要从定义开始。）

## 为什么会有这个问题

（背景、来历、别人怎么解决的。）

> [!要点]
> 这一章最要紧的一句话。

## 先看清楚形状

（一张图，文字直接标在图上。）

## 动手之前，先预测

运行下面这段之前，先想三个问题：

1. …
2. …
3. …

## 第一步：做最简单的那件事

（两三句话说要做什么。）

    ```python
    # 6 到 15 行
    ```

（一两句说输出是什么，几句解释它说明了什么。）

## 第二步：上面那样不够，因为……

（发现问题，引出下一段代码。）

    ```python
    # 又一小段
    ```

（继续解释。如此往复。）

> [!坑]
> 一个容易踩的错。

## 本章小结

- …
- …

## 练习

**第一题（不写代码）。** …

**第二题（改代码）。** …

## 随堂自测

    ```quiz
    - 题目: …
      选项:
        A: …
        B: …
      答案: B
      解析: …
    ```

## 设计笔记：（可选）

（讨论取舍，明说可以跳过。）
```

（模板里的围栏多缩进了四格是为了展示，实际写的时候顶格。）
