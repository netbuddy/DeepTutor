# 事件流

上一章的消息是**结果**——一轮结束后才有的东西。但用户不能等：模型吐字要边吐边显示，
工具跑起来要立刻看到「正在执行 read_file」，出错要马上知道。

所以 agent 内部需要一条**事件流**：正在发生的每一件事都作为一个事件发出去，
谁想看谁订阅。这一章把它建起来。

## 事件有哪些

先想清楚订阅者关心什么，再定类型。少了不够用，多了没人看。

| 事件 | 什么时候发 | 订阅者拿它做什么 |
|---|---|---|
| `text_delta` | 模型每吐出一小段文字 | 追加到界面上，打字机效果 |
| `tool_start` | 开始执行某个工具 | 显示「正在执行 …」 |
| `tool_end` | 工具执行完 | 显示结果或错误 |
| `message_done` | 一条完整消息组装好了 | 存进历史 |
| `turn_done` | 这一轮彻底结束 | 解除输入框的禁用状态 |
| `error` | 出岔子了 | 报错 |

## 本章起点

上一章的消息类型，这里重新定义一遍——每一章是独立的一页，页与页之间不共享状态。

```python
from __future__ import annotations
from dataclasses import dataclass, field
from typing import Any, Literal
import uuid

def new_id(prefix: str) -> str:
    return f"{prefix}_{uuid.uuid4().hex[:12]}"

@dataclass
class TextBlock:
    text: str
    type: Literal["text"] = "text"

@dataclass
class ToolUseBlock:
    name: str
    args: dict[str, Any]
    id: str = field(default_factory=lambda: new_id("call"))
    type: Literal["tool_use"] = "tool_use"

@dataclass
class ToolResultBlock:
    tool_use_id: str
    content: str
    is_error: bool = False
    type: Literal["tool_result"] = "tool_result"

Block = TextBlock | ToolUseBlock | ToolResultBlock

@dataclass
class Message:
    role: Literal["system", "user", "assistant", "tool"]
    content: list[Block]
    id: str = field(default_factory=lambda: new_id("msg"))
    def text(self) -> str:
        return "".join(b.text for b in self.content if isinstance(b, TextBlock))

print("上一章的类型已就位")
```

## 事件类型与事件流

```python
from dataclasses import dataclass
from typing import Callable

@dataclass
class Event:
    kind: str                       # text_delta / tool_start / tool_end / message_done / turn_done / error
    data: dict


class EventStream:
    """最小的发布订阅。

    订阅者是一个普通函数，收到事件就处理。这里刻意不做成异步队列——
    发布方和订阅方在同一个事件循环里，直接调用最省事，也最好调试。
    出错的订阅者不能影响别的订阅者，更不能把发布方带崩。
    """

    def __init__(self) -> None:
        self._subscribers: list[Callable[[Event], None]] = []

    def subscribe(self, fn: Callable[[Event], None]) -> Callable[[], None]:
        self._subscribers.append(fn)
        def unsubscribe() -> None:
            if fn in self._subscribers:
                self._subscribers.remove(fn)
        return unsubscribe          # 返回退订函数，比记住 fn 再传回来方便

    def emit(self, kind: str, **data) -> None:
        event = Event(kind=kind, data=data)
        for fn in list(self._subscribers):     # 复制一份：订阅者可能在回调里退订
            try:
                fn(event)
            except Exception as exc:
                print(f"  [订阅者出错，已忽略] {type(exc).__name__}: {exc}")


# 试一下
stream = EventStream()
stream.subscribe(lambda e: print(f"  收到 {e.kind}: {e.data}"))
stream.emit("text_delta", delta="你好")
stream.emit("tool_start", name="get_time")
```

## 一个会出错的订阅者不该拖垮别人

```python
stream = EventStream()

stream.subscribe(lambda e: print(f"  正常订阅者 A：{e.kind}"))
def broken(e):
    raise ValueError("我坏了")
stream.subscribe(broken)
stream.subscribe(lambda e: print(f"  正常订阅者 B：{e.kind}"))

stream.emit("text_delta", delta="测试")
print("发布方没有被带崩，A 和 B 都收到了。")
```

## 把它接进流程：边吐边显示

现在让假模型一个字一个字地吐，订阅者实时打印。这就是打字机效果的全部原理。

```python
import time

def fake_streaming_model(prompt: str, stream: EventStream) -> Message:
    """假模型：把回答切成小段，一段段发出去，最后组装成一条完整消息。"""
    answer = "北京现在是下午 2 点 32 分。"
    collected = []
    for i in range(0, len(answer), 3):        # 每次吐三个字，模拟真实的分块
        piece = answer[i : i + 3]
        collected.append(piece)
        stream.emit("text_delta", delta=piece)
        time.sleep(0.05)                       # 真实模型的间隔，这里放慢一点便于观察

    message = Message(role="assistant", content=[TextBlock(text="".join(collected))])
    stream.emit("message_done", message_id=message.id, text=message.text())
    return message


stream = EventStream()

# 订阅者一：模拟界面，逐字追加
buffer = []
def on_ui(e: Event) -> None:
    if e.kind == "text_delta":
        buffer.append(e.data["delta"])
        print(f"\r界面上现在显示：{''.join(buffer)}", end="", flush=True)
    elif e.kind == "message_done":
        print(f"\n（消息 {e.data['message_id']} 已完成）")

# 订阅者二：模拟日志，只记大事
def on_log(e: Event) -> None:
    if e.kind != "text_delta":
        print(f"[日志] {e.kind}")

stream.subscribe(on_ui)
stream.subscribe(on_log)

msg = fake_streaming_model("北京现在几点？", stream)
print("最终消息：", msg.text())
```

跑一下能看到：文字是一段段出现的，而日志订阅者完全不关心 `text_delta`，只在消息完成时
记一笔。**同一条流，不同订阅者各取所需**——这就是事件流的价值。

## 为什么不用回调参数

有人会想：直接给模型函数传一个 `on_delta` 回调不就行了吗？

一开始行，等到事件变多就不行了。工具开始、工具结束、错误、轮次结束……每加一种就要多
一个参数，而且这些参数要从最外层一路传到最里层。事件流把这件事收成一个对象：
**发布方只管发，订阅方只管挑自己关心的**，中间层什么都不用知道。

pi 里这个东西叫 `EventStream`，Anthropic 的 SDK 里叫 stream events，本质都是一样的。

## 本章小结

- agent 内部需要一条事件流，把「正在发生什么」实时送出去。
- 订阅者各取所需：界面只看文字增量，日志只看大事。
- **一个订阅者出错不能影响别人，更不能带崩发布方**。
- 遍历订阅者时要**先复制一份列表**，因为订阅者可能在回调里退订自己。
