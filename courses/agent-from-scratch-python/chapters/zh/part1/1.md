# 全景：agent 到底在做什么

「AI agent」这个词被用得很滥。开始写代码之前，我们先把它拆成一句能落到程序上的话：

> **一个 agent 就是一个循环**：把对话历史交给模型 → 模型要么说话、要么要求调用工具 →
> 如果它要调工具，就执行工具、把结果追加进历史 → 回到第一步。直到模型不再要求调工具为止。

就这么多。剩下的复杂度全都来自这句话的边角：消息怎么表示、结果怎么流式吐出来、
历史太长怎么办、工具出错怎么办、进程重启后怎么接上。这门课就是把这些边角一个个补齐。

## 一次完整的往返

假设用户问「北京现在几点？」，而 agent 有一个 `get_time` 工具。实际发生的是：

```
用户 ──「北京现在几点？」──▶ agent
                              │
                              │ 把历史 + 工具声明发给模型
                              ▼
                            模型 ──▶「我要调 get_time(city='北京')」
                              │
                              │ agent 执行这个工具
                              ▼
                          get_time ──▶「14:32」
                              │
                              │ 把工具结果追加进历史，再发给模型
                              ▼
                            模型 ──▶「北京现在是下午 2 点 32 分。」
                              │
用户 ◀──────────────────────────┘
```

注意几件事：

1. **模型自己不会执行任何东西。** 它只能"说"它想调什么工具、传什么参数。真正去执行的
   是我们写的代码。这是 agent 里最容易被误解的一点。
2. **一轮对话里可能来回好几次。** 模型可能先查时间、再查天气，最后才组织语言回答。
3. **历史是一直在长的。** 每一次工具调用和结果都要追加进去，否则模型下一轮就不记得
   自己刚才干了什么。

## 我们要造的东西

这门课最终会得到一个能干活的编码 agent。倒过来看，它由这些部件组成：

| 部件 | 职责 | 在第几章 |
|---|---|---|
| 消息与内容块 | 把一轮对话表示成可存可传的结构 | 2 |
| 事件流 | 让外界能实时看到「正在发生什么」 | 3 |
| 消息存储 | 把历史记下来，能回放 | 4 |
| 模型接口 | 屏蔽掉具体是哪家模型 | 5、6、7 |
| 工具 | 声明、校验、执行 | 9 |
| 主循环 | 上面那个循环的真身 | 10 |
| 会话状态 | 多轮、持久化、分支 | 13、14、15 |
| 上下文压缩 | 历史太长时怎么办 | 16 |

## 先跑一个桩

下面这段代码把上面那张图**写成能跑的形式**，但所有部件都是假的——模型是写死的，
工具也是写死的。它的意义在于：**整条流程的骨架在第一章就完整了**，后面十九章做的
全是把某个假部件换成真的。

运行它，你会看到那次往返的每一步。

```python
# 全程假的：假模型、假工具、假历史。目的是把流程走一遍，看清楚每一步的输入输出。

def fake_model(history):
    """假模型。看到历史里还没有工具结果，就要求调工具；有了就给最终回答。"""
    has_tool_result = any(m["role"] == "tool" for m in history)
    if has_tool_result:
        result = [m for m in history if m["role"] == "tool"][-1]["content"]
        return {"type": "text", "text": f"北京现在是 {result}。"}
    return {"type": "tool_call", "name": "get_time", "args": {"city": "北京"}}


def get_time(city):
    """假工具。真的实现会去查系统时间或者调接口。"""
    return "14:32"


TOOLS = {"get_time": get_time}


def run(user_input):
    history = [{"role": "user", "content": user_input}]
    print(f"用户：{user_input}\n")

    for round_no in range(1, 6):          # 加个上限，防止模型一直要求调工具
        print(f"── 第 {round_no} 轮 ──")
        reply = fake_model(history)

        if reply["type"] == "text":
            print(f"模型：{reply['text']}")
            history.append({"role": "assistant", "content": reply["text"]})
            return reply["text"]

        # 模型要求调工具：它只是"说"，执行的是我们
        name, args = reply["name"], reply["args"]
        print(f"模型：我要调 {name}({args})")
        history.append({"role": "assistant", "content": f"[调用 {name}]"})

        output = TOOLS[name](**args)
        print(f"工具：{name} 返回 {output}")
        history.append({"role": "tool", "content": output})

    return "循环次数用完了"


run("北京现在几点？")
```

## 读一下历史长什么样

再跑一段，把最终的历史打印出来。**注意工具调用和工具结果都在里面**——
这就是模型"记得自己刚才干了什么"的全部秘密。

```python
import json

history = [{"role": "user", "content": "北京现在几点？"}]
reply = fake_model(history)
history.append({"role": "assistant", "content": f"[调用 {reply['name']}]"})
history.append({"role": "tool", "content": get_time(**reply["args"])})
reply = fake_model(history)
history.append({"role": "assistant", "content": reply["text"]})

print(json.dumps(history, ensure_ascii=False, indent=2))
```

## 这个桩有什么问题

它能跑，但离能用差得远。逐条数一下，正好就是后面各章的题目：

- 消息只有 `role` 和 `content` 两个字段。**真实的一条助手消息里可能同时有文字和多个
  工具调用**，一个字符串装不下。（第 2 章）
- 全程是同步的，模型"回答"是一次性蹦出来的。**真实的模型是一个字一个字吐的**，
  用户要能实时看到。（第 3 章）
- 历史存在内存里的一个列表中，程序一退就没了。（第 4 章）
- `fake_model` 是写死的。（第 5 到 8 章）
- 工具是一个字典，没有参数校验，模型传错参数就崩。（第 9 章）
- 循环上限写死成 5，工具出错没人管，用户想中途打断也没办法。（第 10 到 12 章）

## 本章小结

- agent 的本质是**一个循环**：模型说要调工具，我们执行，结果回填进历史，再问模型。
- **模型自己不执行任何东西**，它只能表达意图。
- **历史是 agent 的记忆**，工具调用和结果都要记进去。
- 我们已经有一个能跑的骨架了。接下来十九章，是把里面每个假部件换成真的。
