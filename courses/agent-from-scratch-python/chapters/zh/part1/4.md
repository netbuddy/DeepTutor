# 消息存储

历史现在还在内存里的一个列表中，程序一退就没了。这一章把它存到磁盘上。

看起来是个小问题，但存储格式的选择会影响后面好几章：**会话能不能续上**（第 14 章）、
**能不能从中间分叉**（第 15 章）、**上下文压缩后原始记录还在不在**（第 16 章），
全都取决于这里怎么存。

## 为什么是 JSONL 而不是一个大 JSON

最直觉的做法是把整个历史序列化成一个 JSON 数组写进文件。别这么做：

| 做法 | 追加一条消息 | 进程被杀 | 读取 |
|---|---|---|---|
| 一个大 JSON 数组 | 要读出整个文件、改、再整个写回 | 写到一半 → **整个文件废了** | 必须整个读进内存 |
| 一行一条（JSONL） | 直接往文件尾追加一行 | 写到一半 → **只有最后一行不完整，前面全在** | 可以边读边处理 |

JSONL 就是「每行一个 JSON 对象」。pi 用的是这个，大多数 agent 框架也是。**追加只写不改**
这个性质，是它比数据库和大 JSON 都更适合会话历史的原因——历史本来就是只增不改的。

## 本章起点

```python
from __future__ import annotations
from dataclasses import dataclass, field, asdict
from typing import Any, Literal
import uuid

def new_id(prefix: str) -> str:
    return f"{prefix}_{uuid.uuid4().hex[:12]}"

@dataclass
class TextBlock:
    text: str
    type: Literal["text"] = "text"

@dataclass
class ToolUseBlock:
    name: str
    args: dict[str, Any]
    id: str = field(default_factory=lambda: new_id("call"))
    type: Literal["tool_use"] = "tool_use"

@dataclass
class ToolResultBlock:
    tool_use_id: str
    content: str
    is_error: bool = False
    type: Literal["tool_result"] = "tool_result"

@dataclass
class Message:
    role: Literal["system", "user", "assistant", "tool"]
    content: list[Any]
    id: str = field(default_factory=lambda: new_id("msg"))
    def text(self) -> str:
        return "".join(b.text for b in self.content if isinstance(b, TextBlock))

_BLOCK_TYPES = {"text": TextBlock, "tool_use": ToolUseBlock, "tool_result": ToolResultBlock}

def message_to_dict(m: Message) -> dict:
    return {"id": m.id, "role": m.role, "content": [asdict(b) for b in m.content]}

def message_from_dict(d: dict) -> Message:
    blocks = []
    for raw in d["content"]:
        raw = dict(raw)
        cls = _BLOCK_TYPES.get(raw.pop("type"))
        if cls is not None:
            blocks.append(cls(**raw))
    return Message(id=d["id"], role=d["role"], content=blocks)

print("上两章的类型已就位")
```

## 存储实现

```python
import json
import os
import tempfile
from pathlib import Path


class JsonlStore:
    """一行一条消息的会话存储。

    只提供两个动作：追加、读全部。刻意不提供"改某一条"——历史是只增不改的，
    需要修正时应当追加一条新的，而不是改旧的。这条约束让崩溃恢复变得简单：
    最坏情况是最后一行写了一半，丢掉它就行，前面的全都完好。
    """

    def __init__(self, path: str | Path) -> None:
        self.path = Path(path)
        self.path.parent.mkdir(parents=True, exist_ok=True)

    def append(self, message: Message) -> None:
        line = json.dumps(message_to_dict(message), ensure_ascii=False)
        with open(self.path, "a", encoding="utf-8") as f:
            f.write(line + "\n")
            f.flush()
            os.fsync(f.fileno())      # 真落盘，否则进程被杀时缓冲区里的还没写下去

    def load(self) -> list[Message]:
        if not self.path.exists():
            return []
        messages, broken = [], 0
        with open(self.path, encoding="utf-8") as f:
            for line in f:
                line = line.strip()
                if not line:
                    continue
                try:
                    messages.append(message_from_dict(json.loads(line)))
                except (json.JSONDecodeError, KeyError, TypeError):
                    # 只可能是最后一行写了一半。跳过它，别让整个会话读不出来。
                    broken += 1
        if broken:
            print(f"  （跳过了 {broken} 行读不出来的记录）")
        return messages

    def count(self) -> int:
        if not self.path.exists():
            return 0
        with open(self.path, encoding="utf-8") as f:
            return sum(1 for line in f if line.strip())


store = JsonlStore("/tmp/agent-course/session-demo.jsonl")
print("存储就绪：", store.path)
```

## 存一轮对话再读回来

```python
import shutil

# 每次运行先清空，免得反复运行越积越多
shutil.rmtree("/tmp/agent-course", ignore_errors=True)
store = JsonlStore("/tmp/agent-course/session-demo.jsonl")

call = ToolUseBlock(name="get_time", args={"city": "北京"})
for m in [
    Message(role="user", content=[TextBlock(text="北京现在几点？")]),
    Message(role="assistant", content=[TextBlock(text="我查一下。"), call]),
    Message(role="tool", content=[ToolResultBlock(tool_use_id=call.id, content="14:32")]),
    Message(role="assistant", content=[TextBlock(text="北京现在是 14:32。")]),
]:
    store.append(m)

print("文件里有", store.count(), "行\n")
print("文件原文：")
print(store.path.read_text(encoding="utf-8"))

print("读回来：")
for m in store.load():
    print(f"  {m.role:10} {m.text() or '（无文字）'}")
```

注意看文件原文——**每一行都是一个完整的 JSON**，用文本工具就能查看和统计，
不需要专门的程序。这是 JSONL 的另一个好处。

## 崩溃恢复：故意写坏最后一行

```python
# 模拟进程在写第五条消息时被杀：文件尾多了半行
with open(store.path, "a", encoding="utf-8") as f:
    f.write('{"id": "msg_broken", "role": "assist')     # 故意不写完，也不换行

print("现在文件的最后 40 个字符：", repr(store.path.read_text(encoding="utf-8")[-40:]))
print()
messages = store.load()
print(f"仍然读出了 {len(messages)} 条消息，前面的记录一条没丢：")
for m in messages:
    print(f"  {m.role:10} {m.text() or '（无文字）'}")
```

这就是 JSONL 的关键性质：**坏也只坏最后一行**。换成一个大 JSON 数组，这个文件现在
已经完全读不出来了。

## 一个容易忽略的点：fsync

`append` 里调了 `os.fsync`。不调的话，`write` 只是把数据交给操作系统的缓冲区，
进程被强杀时那些数据还没落盘。对会话历史来说，「用户明明看到助手回答了，重启后却
不见了」是很糟糕的体验，值得为此付出每次写入的一点开销。

真实系统里会做批量刷盘来平衡性能，但**默认应该是安全的那一边**。

## 本章小结

- 会话历史用 **JSONL**：一行一条，只追加不修改。
- 只追加换来两件事：**写入快**（不用读改写整个文件），**坏只坏最后一行**。
- 读取时要**容忍读不出来的行**，跳过而不是报错。
- `write` 之后要 `fsync`，否则进程被杀时数据还在缓冲区里。
