# 从零实现一个 AI Agent（Go 版）

二十章，从一个「把消息发给模型再收回来」的循环，走到一个能改文件、能执行命令、
能记住对话、能按需学技能、能被度量的 agent。

参照 [pi-agent-core](https://github.com/earendil-works/pi) 的实际结构，按渐进路径重排——
**每一章解决一个具体问题，每一章结束时手里的东西都能编译、能跑**。

这门课不是把 pi 的三万行翻译一遍。那里面大部分代码在处理各家模型供应商的差异，
对理解 agent 原理没有帮助。目标是：**读完这门课，再去看 pi 的源码能看懂**。

## 五个部分

| 部分 | 章 | 解决什么 |
|---|---|---|
| 一、骨架与协议 | 1-5 | 消息与内容块、事件流、消息存储、脚本化的假模型 |
| 二、接上真模型 | 6-8 | 供应商适配、流式解析、把假模型换成真的而调用方一行不改 |
| 三、agent 的心脏 | 9-12 | 工具契约、主循环、并发与取消、模型不听话时怎么办 |
| 四、记忆 | 13-16 | 有状态的 agent、会话持久化、会话树、上下文压缩 |
| 五、干活的 agent | 17-20 | 编码工具、权限与沙箱、技能、评估 |

## 几条贯穿全书的判断

- **先定接口，再写实现**。Go 的接口是隐式实现的，这件事几乎没有成本。
- **每个工具调用都必须有对应的结果**。取消、分叉、压缩全都受这条约束。
- **提示词不是安全边界**。真正的边界必须是代码里的机制。
- **能用代码保证的，不要用文字请求。**
- 没有评估集，改提示词就是玄学。

## 顺带收下的 Go 经验

这些和 agent 无关，但写任何 Go 服务都用得上：

- `context.Context` 要**一开始就放进签名**，晚加的代价你会在第 11 章亲自付一次。
- 往通道里写要 `select` 上 `ctx.Done()`，否则取消之后生产者永远卡住。
- `recover` 是工具执行的必备防线，一个工具的 bug 不该炸穿整个进程。
- `json.Unmarshal` **解不进接口**，要两趟解码加 `json.RawMessage`。
- `bufio.Scanner` 默认单行上限 64 KB。
- map 元素**不可寻址**，遍历顺序**随机**。
- `exec.Command` **不经过 shell**，而 `cmd.Env` 为 nil 时**继承全部环境变量**。

## 页面上的代码怎么跑

Go 是编译型语言，没有像 Python 那样的长驻内核，所以这里用的是**累积编译**：
同一页里前面格子写下的文件会保留，点「运行」时把这一页到当前格为止的所有文件
凑齐一起编译。

每格开头那行 `// file: xxx.go` 决定它写进哪个文件，同名会覆盖——
**所以跨格子要用的常量和函数不要写在 `main.go` 里**，后面每一格都有自己的 `main`。

没有 `main` 函数的格子只做编译检查（`go vet`），有 `main` 的格子会真的跑起来。
换一页就是全新的开始，所以每一章开头都有一格「本章起点」，把前面章节的成果一次性铺好。

课文里的模型地址指向局域网里的一个本地模型。换成你自己的地址即可，接口是 OpenAI 兼容的。

能看清同一个机制在两种语言里的不同写法。
