# 全景：agent 到底在做什么

「AI agent」这个词被用得很滥。开始写代码之前，我们先把它拆成一句能落到程序上的话：

> **一个 agent 就是一个循环**：把对话历史交给模型 → 模型要么说话、要么要求调用工具 →
> 如果它要调工具，就执行工具、把结果追加进历史 → 回到第一步。直到模型不再要求调工具为止。

就这么多。剩下的复杂度全都来自这句话的边角：消息怎么表示、结果怎么流式吐出来、
历史太长怎么办、工具出错怎么办、进程重启后怎么接上。这门课就是把这些边角一个个补齐。

## 一次完整的往返

假设用户问「北京现在几点？」，而 agent 有一个 `get_time` 工具：

```
用户 ──「北京现在几点？」──▶ agent
                              │
                              │ 把历史 + 工具声明发给模型
                              ▼
                            模型 ──▶「我要调 get_time(city='北京')」
                              │
                              │ agent 执行这个工具
                              ▼
                          get_time ──▶「14:32」
                              │
                              │ 把工具结果追加进历史，再发给模型
                              ▼
                            模型 ──▶「北京现在是下午 2 点 32 分。」
                              │
用户 ◀──────────────────────────┘
```

三件容易被误解的事：

1. **模型自己不会执行任何东西。** 它只能"说"它想调什么工具、传什么参数。真正去执行的
   是我们写的代码。
2. **一轮对话里可能来回好几次。** 模型可能先查时间、再查天气，最后才组织语言回答。
3. **历史是一直在长的。** 每一次工具调用和结果都要追加进去，否则模型下一轮就不记得
   自己刚才干了什么。

## 关于这门课的 Go 版

这门课有 Go 和 Python 两个版本，大纲一样，但**不是逐行翻译**。同一个机制在两种语言里
的地道写法不同，硬翻会两边都别扭：

| 机制 | Python 版怎么写 | Go 版怎么写 |
|---|---|---|
| 事件流 | 订阅回调 / 异步生成器 | 通道（channel） |
| 并发工具调用 | `asyncio.gather` | goroutine 加 `sync.WaitGroup` |
| 取消 | `asyncio.CancelledError` | `context.Context` |
| 错误 | 抛异常 | 显式返回 `error` |
| 抽象 | `Protocol` | `interface` |

**页面上的代码怎么跑**：Go 是编译型语言，没有像 Python 那样的长驻内核。这一页里的每
一格代码是模块里的一个文件，点「运行」时会把这一页到当前格为止的所有文件凑齐一起编译。
所以每格开头那行 `// file: xxx.go` 很重要——它固定了这段代码写进哪个文件，
你反复运行也不会积出重复定义。

还没有 `main` 函数的章节，点运行会做类型检查，通过就说明这一步写对了。

## 先跑一个桩

下面把上面那张图**写成能跑的形式**，但所有部件都是假的。它的意义在于：
**整条流程的骨架在第一章就完整了**，后面十九章做的全是把某个假部件换成真的。

先定义最粗糙的消息和假部件：

```go
// file: stub.go
package main

import "fmt"

// Msg 是这一章临时用的消息表示。下一章会发现它不够用。
type Msg struct {
	Role    string // user / assistant / tool
	Content string
}

// Reply 是假模型的回复：要么是一段文字，要么是一次工具调用。
type Reply struct {
	IsToolCall bool
	Text       string
	ToolName   string
	ToolArgs   map[string]string
}

// fakeModel 假模型：历史里还没有工具结果就要求调工具，有了就给最终回答。
func fakeModel(history []Msg) Reply {
	for _, m := range history {
		if m.Role == "tool" {
			return Reply{Text: fmt.Sprintf("北京现在是 %s。", m.Content)}
		}
	}
	return Reply{
		IsToolCall: true,
		ToolName:   "get_time",
		ToolArgs:   map[string]string{"city": "北京"},
	}
}

// getTime 假工具。真实实现会去查系统时间或者调接口。
func getTime(args map[string]string) string {
	return "14:32"
}
```

这一格只有类型和函数，没有 `main`，所以点运行只会做类型检查。下一格补上主循环：

```go
// file: main.go
package main

import "fmt"

func run(userInput string) string {
	history := []Msg{{Role: "user", Content: userInput}}
	fmt.Printf("用户：%s\n\n", userInput)

	for round := 1; round <= 5; round++ { // 加个上限，防止模型一直要求调工具
		fmt.Printf("── 第 %d 轮 ──\n", round)
		reply := fakeModel(history)

		if !reply.IsToolCall {
			fmt.Printf("模型：%s\n", reply.Text)
			history = append(history, Msg{Role: "assistant", Content: reply.Text})
			return reply.Text
		}

		// 模型要求调工具：它只是"说"，执行的是我们
		fmt.Printf("模型：我要调 %s(%v)\n", reply.ToolName, reply.ToolArgs)
		history = append(history, Msg{
			Role:    "assistant",
			Content: fmt.Sprintf("[调用 %s]", reply.ToolName),
		})

		output := getTime(reply.ToolArgs)
		fmt.Printf("工具：%s 返回 %s\n", reply.ToolName, output)
		history = append(history, Msg{Role: "tool", Content: output})
	}
	return "循环次数用完了"
}

func main() {
	run("北京现在几点？")
}
```

## 看看历史长什么样

把最终的历史打印出来。**工具调用和工具结果都在里面**——这就是模型"记得自己刚才干了
什么"的全部秘密。

```go
// file: dump.go
package main

import (
	"encoding/json"
	"fmt"
)

func dumpHistory() {
	history := []Msg{{Role: "user", Content: "北京现在几点？"}}
	reply := fakeModel(history)
	history = append(history,
		Msg{Role: "assistant", Content: fmt.Sprintf("[调用 %s]", reply.ToolName)},
		Msg{Role: "tool", Content: getTime(reply.ToolArgs)},
	)
	reply = fakeModel(history)
	history = append(history, Msg{Role: "assistant", Content: reply.Text})

	raw, _ := json.MarshalIndent(history, "", "  ")
	fmt.Println(string(raw))
}
```

这一格定义了函数但没调用它。改一下上面那个 `main.go` 格子，在 `main` 里加一行
`dumpHistory()` 再运行，就能看到完整历史。**试着自己改一次**——课本里的代码是可以改的，
改坏了点「还原」。

## 这个桩有什么问题

它能跑，但离能用差得远。逐条数一下，正好就是后面各章的题目：

- `Msg.Content` 是一个字符串。**真实的一条助手消息里可能同时有文字和多个工具调用**，
  一个字符串装不下。（第 2 章）
- 全程是同步的，模型"回答"是一次性蹦出来的。**真实的模型是一个字一个字吐的**。（第 3 章）
- 历史存在切片里，程序一退就没了。（第 4 章）
- `fakeModel` 是写死的。（第 5 到 8 章）
- 工具的参数是 `map[string]string`，没有校验，模型传错就崩。（第 9 章）
- 循环上限写死成 5，工具出错没人管，用户想中途打断也没办法。（第 10 到 12 章）

## 本章小结

- agent 的本质是**一个循环**：模型说要调工具，我们执行，结果回填进历史，再问模型。
- **模型自己不执行任何东西**，它只能表达意图。
- **历史是 agent 的记忆**，工具调用和结果都要记进去。
- Go 版里每一格是模块里的一个文件，运行时累积编译；`// file:` 那行注释固定文件名。
