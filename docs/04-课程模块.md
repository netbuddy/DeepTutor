# 课程模块

把外部课程取进来，变成可读、可练、可检索的一门课。这一篇讲数据模型、导入流程，以及怎么支持新的课程排布。

---

## 一门课摊成三样东西

| 产出 | 落在哪 | 谁在用 |
|---|---|---|
| 课程目录 | `data/user/courses/<标识>/` | 执行容器只读挂载这一份；跑代码时的工作目录在里面 |
| 一本书 | `data/user/workspace/book/book_<id>/` | 学生在书籍页里读和练 |
| 一个检索索引 | 知识库 `course-<标识>` | 绑在书上，书页对话面板据此翻遍整门课回答 |

三者之间唯一的连接点是**课程清单**（`data/user/settings/ext_courses.json`），删课时靠它把三边一起清干净。

清单里一条记录长这样：

```json
{
  "slug": "hf-llm-course",
  "title": "Hugging Face LLM 课程",
  "origin": "https://github.com/huggingface/course.git",
  "kind": "git",
  "layout": "toctree",
  "language": "zh",
  "book_id": "bk_course_hf-llm-course",
  "kb_name": "course-hf-llm-course",
  "size_mb": 24.6,
  "stats": {"chapters": 12, "pages": 78, "text_blocks": 2176,
            "code_blocks": 128, "runnable_cells": 128, "skipped_files": 0},
  "imported_at": 1785571408.26,
  "indexed_at": 1785571994.81
}
```

## 模块划分

`deeptutor_ext/course/`：

| 文件 | 职责 |
|---|---|
| `sources.py` | 把「用户给的一个来源」变成课程目录下的一份本地内容（克隆或复制） |
| `layouts.py` | 识别课程目录是哪种排布，按各自的规矩读成统一形状 |
| `notebook_io.py` | 读 `.ipynb`，拆成一格一格，整理已存输出 |
| `importer.py` | 把读好的结构写成一本 Book |
| `service.py` | 生命周期门面：取来源、导成书、建索引、登记、删除 |

关键的设计是 `layouts.py` 产出的**统一形状**——`CourseTree`（章 → 课 → 片段），片段要么是讲解要么是代码。导入器只认这个形状，所以再多一种课程排布也只要在 `layouts.py` 加一个识别函数，导入器一行都不用动。

## 目前认得两种排布

### 讲义配 notebook（`layout: notebook`）

microsoft/ML-For-Beginners 是这一类：

```
2-Regression/                     模块 → 章
├── README.md                     模块导读 → 章标题
├── data/US-pumpkins.csv          本模块共用的数据集
├── 1-Tools/                      课时 → 页
│   ├── README.md                 讲义 → 若干文本块
│   ├── notebook.ipynb            练习（多数是空壳）
│   ├── solution/notebook.ipynb   答案（完整可运行）→ 逐格变成块
│   └── assignment.md             作业 → 若干文本块
```

**为什么优先用答案本**：课程给学生的练习本多数只有一个空格子，没有教学内容；带讲解和完整代码的是答案本，它才是可以逐格运行的教学材料。挑选顺序是 `solution/notebook.ipynb` → `notebook.ipynb` → 目录下任意有代码格的 `.ipynb`（跳过 R 语言版本，内核只有 Python）。

### 目录树配正文（`layout: toctree`）

huggingface/course 是这一类：

```
chapters/
├── zh-CN/
│   ├── _toctree.yml        章节树：章标题 + 每章的课列表
│   ├── chapter1/1.mdx      正文，代码写在围栏里
│   └── chapter2/...
└── en/...
```

`_toctree.yml` 的结构很规整（只有 title / sections / local 三种键），所以手写解析，省掉一个 YAML 依赖。格式变了会解析成空，这时会退回按目录扫描。

语言选择：找不到指定语言就退回英文，再不行取第一个。中文写 `zh` 能匹配到 `zh-CN`。

正文是 MDX——Markdown 里混着 React 组件。清洗规则：

| 处理 | 例子 |
|---|---|
| 删掉 import 语句 | `import Tip from ...` |
| 成对标签只脱外壳、保留内容 | `<Tip>这句话有用</Tip>` → `这句话有用` |
| 自闭合组件整个删掉 | `<Youtube id="..." />` |
| 标题后缀的锚点删掉 | `# 标题[[anchor]]` → `# 标题` |

然后按代码围栏切开：围栏外是讲解，围栏内是代码。语言是 `py` / `python` / `python3` 的标记为可运行，其余（bash、json 等）作为代码展示但不可运行。

## 导入流程

```mermaid
flowchart LR
  A["用户填来源<br/>Git 地址或本地目录"] --> B["sources.fetch<br/>浅克隆或复制到课程目录"]
  B --> C["layouts.detect_layout<br/>识别排布"]
  C --> D["layouts.read_course<br/>读成 CourseTree"]
  D --> E["importer.save<br/>写成 Book"]
  E --> F["service 登记进课程清单"]
  F -.可选.-> G["build_index<br/>导出正文 → 建知识库 → 绑到书上"]
```

### 取来源

克隆一律用**浅克隆且不取子模块**：课程仓库往往带着几十种语言的翻译和历史插图，完整历史动辄上 GB，而学习只需要当前这一份。超时 900 秒。

`GIT_TERMINAL_PROMPT=0` —— 私有仓库直接失败，比挂住等用户名密码好。

本地目录来源会**复制**到课程目录下，不能原地引用：执行容器只挂了课程目录那一个位置，放在别处页面能显示但代码跑不起来。

### 哪些目录不跟着导入

```
translations, quiz-app, node_modules, pdf, .git, .github,
sketchnotes, subtitles, utils, images, assets
```

**`translations` 这一条最要紧**：ML-For-Beginners 有 2856 个 notebook，去掉 55 种语言的翻译副本后只剩 51 个。不排除的话会把同一课的 55 个语言版本一起塞进检索库，检索质量被严重稀释。

### 块的映射

课程片段 → Book 的内容块：

| 片段 | 块类型 | payload |
|---|---|---|
| 讲解 | `text` | `{markdown, text}` |
| 代码 | `code` | `{language, code, explanation, notebook: {...}}` |

`notebook` 那一段是我们加的，前端认得它就给这一段画运行按钮：

```json
"notebook": {
  "source": "chapters/zh-CN/chapter2/2.mdx",   // 出处，显示与追溯用
  "cwd": "/…/courses/hf-llm-course/chapters/zh-CN/chapter2",  // 执行时的工作目录
  "cell_index": 3,          // 界面上显示的编号
  "runnable": true,
  "saved_output": "…",      // 课程里存的运行结果，还没跑时先给学生看
  "saved_image_count": 1
}
```

**为什么复用 `code` 块类型而不是新增一种**：Book 的块类型是后端的一个枚举，加值要改源码；而块模型允许自定义字段（`model_config = ConfigDict(extra="allow")`，payload 是自由字典）。复用 + 自定义字段 = **后端零改动**，前端只需在分派处多一个判断。认不得这段信息的地方（比如旧版前端）会退化成一段普通的代码展示，不会出错。

### 长文切段

讲义按二级标题切成若干段，段落过长时按空行再切一刀（默认上限 2500 字符）。切开是为了让页面可以逐段阅读、逐段提问；不切的话一页就是一大坨文字，「就这一段提问」也就无从谈起。

### 坏文件要跳过

外部课程里什么样的文件都有：Git LFS 只签出了指针、文件是空的、编码坏掉、或者干脆不是 JSON。`parse_notebook` 遇到这些抛 `NotebookParseError`，上层捕获后跳过并计数，最后如实报告「跳过 N 个文件」。

不这么做的后果是**一份坏文件让整门课导不进来**——ML-For-Beginners 里就有两个这样的 notebook。

### 重复导入

书的 id 由课程标识派生（`bk_course_<标识>`），所以重复导入是覆盖而不是新增。存盘前会先删掉这次不再出现的旧页：课程结构可能变了，留着上一次的孤儿页会让目录里点开是空白。

## 检索索引与学习流程的接合

这是「融入 DeepTutor 现有学习流程」的关键一环，而且**前端一行都不用改**。

书页的对话面板发起对话时是这么写的：

```tsx
// BookChatPanel.tsx（上游代码）
tools: book.knowledge_bases?.length ? ["rag"] : [],
knowledge_bases: book.knowledge_bases || [],
```

也就是说——**书上绑了知识库，对话就自动开检索工具**。所以我们要做的只是建好知识库并写进 `book.knowledge_bases`。

建索引的过程：

1. 把全课正文摊成一课一个 Markdown 文件，放进 `workspace/course_index/<标识>/`。文件名带章节序号（`01-02-课程简介.md`），这样助教引用出处时学生能直接对上是哪一课。
2. 代码也写进去（带围栏），这样学生问「哪一课出现过 tokenizer」时能检索到代码。图片不跟过来——课程里的插图对文字检索没有帮助，只会撑大索引。
3. 调 DeepTutor 的 `initialize_knowledge_base`（新建）或 `add_documents`（补文档）。
4. 把知识库名字写进书的 `knowledge_bases` 字段。

**半成品知识库的处理**：登记表里有名字不等于索引真的建成过——上一次建到一半失败就会留下这种半成品，补文档时会报「knowledge base not initialized」。碰到这种情况删掉重建，而不是把错误抛给用户。

中间目录放在 `workspace/course_index/` 而不是课程目录里，因为课程目录是原始资料，下次重新导入会被整体替换掉。

## 接口

| 接口 | 说明 |
|---|---|
| `GET /api/v1/ext/course/list` | 列出所有课程。顺手对账：目录被手工删掉的不再出现 |
| `POST /api/v1/ext/course/create` | 取来源 + 导成书。`build_index=true` 时顺带建索引 |
| `POST /api/v1/ext/course/{slug}/index` | 建或重建检索索引，并绑到书上 |
| `POST /api/v1/ext/course/{slug}/delete` | 删除。可分别选择要不要连书和索引一起删 |

`create` 的参数：`origin`（必填）、`title`、`slug`、`language`、`branch`、`replace`、`build_index`。

克隆和解析都是同步的重活，接口里用 `asyncio.to_thread` 放线程里跑，不占住事件循环。

命令行等价写法：

```bash
curl -X POST -H 'Content-Type: application/json' \
  -d '{"origin":"https://github.com/huggingface/course.git","language":"zh","build_index":true}' \
  http://127.0.0.1:9188/api/v1/ext/course/create
```

## 前端

`web/app/(workspace)/course/page.tsx`，新增文件，不碰上游代码。侧栏入口在 `SidebarShell.tsx` 里加一条（唯一的嵌入点）。

页面分两块：上面是新增表单（来源、名称、语言、是否建索引、是否覆盖），下面是课程列表，每门课显示章节数、可运行代码段数、占用、导入时间、索引状态，以及三个动作（打开课本、建／重建索引、删除）。

「打开课本」跳转到 `/book?book=<book_id>`——注意查询参数名是 `book` 不是 `bookId`，上游是这么读的。

## 支持一种新排布要做什么

1. 在 `layouts.py` 的 `detect_layout()` 里加识别条件；
2. 写一个 `read_xxx_layout(root, title, ...)` 返回 `CourseTree`；
3. 在 `read_course()` 里分派过去。

导入器、服务、接口、前端都不用动。

`CourseTree` 的形状：

```python
CourseTree(title, layout, chapters=[
    Chapter(title, key, lessons=[
        Lesson(title, key, fragments=[
            Fragment(kind="text"|"code", body, title, language,
                     runnable, cwd, cell_index, saved_output,
                     saved_image_count, source_label),
        ]),
    ]),
], skipped=["读不了的文件说明", ...])
```

## 已知的边界

- **大仓库占磁盘**：ML-For-Beginners 完整克隆 1.9 GB，其中大部分是翻译副本和插图。目前是全量克隆后按规则跳过，没有做稀疏检出。
- **不跟踪上游更新**：课程导入后是一份快照，上游课程更新了要手工重新导入（勾选覆盖）。
- **索引是全量重建**：`build_index` 每次都把全课重导一遍，没有增量。78 篇文档的规模下可以接受。
- **删除不可撤销**：删课会连课程文件、书、知识库一起删掉，没有回收站。
