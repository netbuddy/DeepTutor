# 部署与运维

## 日常命令

全部在 `~/DeepTutor-ext` 下执行。

```bash
make help            # 命令一览与地址

make install         # 首次安装扩展包与站点钩子（升级流程里会自动跑）
make kernel-build    # 构建执行容器的镜像（第一次要下载一两 GB）
make kernel-start    # 起执行容器；不起的话页面上跑不了代码
make start           # 起 DeepTutor（前端 9187，后端 9188）
make stop
make restart
make status          # 版本、进程、端口
make health          # 前后端各请求一次
make verify          # 接入自检，升级后必跑
make kernel-status   # 执行容器状态与活跃内核数
make manual-start    # 起使用手册的静态服务（make start 会一并起）
make manual-stop
make logs            # 跟踪日志
make upgrade VERSION=v1.5.8   # 升级 DeepTutor 并重新集成
make patches         # 把本地源码改动导出成补丁文件备查
```

启动顺序：**先 `kernel-start` 再 `start`**。反过来也能起，只是在容器起来之前页面上点运行会报「内核容器没有应答」。

## 从零装一套

如果要在另一台机器上重建，按这个顺序：

### 1. 前置

- Python 3.11 到 3.13（这台是 3.12.3）
- Node.js 20 以上（这台是 24.15.0；上游 README 建议 22 LTS，24 实测可用）
- Docker（执行容器要用）
- 一个能用的模型服务：对话模型走 OpenAI 兼容接口，嵌入模型用于知识库

### 2. 取源码并装依赖

```bash
git clone --depth 1 --branch v1.5.7 https://github.com/HKUDS/DeepTutor.git ~/DeepTutor-src
cd ~/DeepTutor-src
python3 -m venv .venv
./.venv/bin/pip install -e .
cd web && npm ci --legacy-peer-deps
```

源码安装模式下前端跑的是 Next.js 开发服务器，不需要生产构建。首次编译一两分钟。

### 3. 配置

`~/DeepTutor-src/data/user/settings/system.json` 定端口：

```json
{"version": 1, "backend_port": 9188, "frontend_port": 9187}
```

`model_catalog.json` 配模型。**供应商必须填 `custom`**（界面上是「Custom (OpenAI API)」）——填 `llama_cpp`、`ollama`、`vllm`、`lm_studio` 这类本地供应商会让 DeepTutor 整轮不下发工具声明，知识库检索会静默失效，界面上看不出任何异常。这一条见 [05-踩坑与决策](05-踩坑与决策.md)。

### 4. 装扩展

```bash
git clone <本仓库> ~/DeepTutor-ext
cd ~/DeepTutor-ext
make install       # pip install -e . + 装站点钩子
make kernel-build  # 构建执行容器镜像
make kernel-start
make start
make verify
```

### 5. 本地源码改动

前端那几处改动在 `~/DeepTutor-src` 的 `local` 分支上。新机器上重放：

```bash
cd ~/DeepTutor-src
git checkout -b local && git tag upstream-base v1.5.7
python3 ~/DeepTutor-ext/frontend-patches/patch_blocks.py
python3 ~/DeepTutor-ext/frontend-patches/patch_ask.py
python3 ~/DeepTutor-ext/frontend-patches/patch_zh.py
python3 ~/DeepTutor-ext/frontend-patches/patch_nav.py
cp ~/DeepTutor-ext/frontend-patches/RunnableCell.tsx \
   "web/app/(workspace)/book/components/blocks/RunnableCell.tsx"
cp ~/DeepTutor-ext/frontend-patches/course-page.tsx \
   "web/app/(workspace)/course/page.tsx"
git add -A && git commit -m "本地改动"
```

也可以直接用 `patches/` 下导出的补丁文件（`git am`），但补丁绑定具体版本，脚本对上游小改动更耐受。

## 升级

```bash
make upgrade VERSION=v1.5.8
```

它按顺序做七件事：

1. 停服务
2. 从上游取新标签（浅克隆会先补全历史）
3. 把 `local` 分支上的本地源码改动变基到新版本
4. 重装后端依赖
5. 重装前端依赖
6. 重新安装扩展并跑接入自检
7. 启动

**只有第三步可能需要人工介入。** 变基冲突时 make 会停下来并打印接下来该敲什么：解决冲突 → `git rebase --continue` → `git tag -f upstream-base <新版本>` → 重跑剩下的步骤。

升级后**一定要看 `make verify` 的输出**。扩展是靠站点钩子挂进宿主的内置工具清单的，一旦上游改了那份清单的名字或位置，接入会**静默失效**——工具只是不出现，界面上看不出任何异常。

## 接入自检 `make verify` 查什么

九项，逐条对照接入契约：

| 检查项 | 不通过意味着 |
|---|---|
| 站点钩子已安装 | `deeptutor_ext.pth` 不在虚拟环境里，重跑 `bin/install-sitehook.py` |
| 宿主仍有 `BUILTIN_TOOL_TYPES` | 上游改了内置工具清单的名字，接入点要跟着改 |
| 宿主仍有 `BUILTIN_TOOL_NAMES` | 同上 |
| 宿主仍有 `CONFIGURABLE_BUILTIN_TOOL_NAMES` | 同上 |
| 宿主的工具注册表接口未变 | `ToolRegistry` 的方法改了 |
| 扩展工具都在注册表里 | 钩子没生效，或工具类实例化失败 |
| 该自动挂载的工具都已登记 | 工具进了注册表但对话不会挂载它 |
| nltk 的工作目录拦截已放宽 | 建知识库会失败，见 [05 篇](05-踩坑与决策.md) |
| 沙箱能真的执行命令 | 代码执行工具与办公文档技能全都不可用 |

最后一项是我们自己实现的，**没有用 DeepTutor 自带的健康探针**——上游那个只看返回结构里的 `error` 字段，而 bubblewrap 失败时是「进程正常启动、正常退出、退出码非零、错误在标准错误里」，`error` 恰好是空的，探针会误报健康。我们的检查改为真跑一条 `echo` 看退出码和输出。

## 执行容器

学生的代码跑在一个独立容器里，宿主与它之间只有一条 HTTP 通道。

```bash
make kernel-build    # 构建镜像（deeptutor-kernel:local）
make kernel-start    # 起容器
make kernel-status   # 状态、活跃内核数
make kernel-logs
make kernel-stop
```

镜像定义在 `kernel-image/Dockerfile`：官方科学计算镜像（pandas、scikit-learn、matplotlib、seaborn）之外，加了 torch 的 CPU 版、transformers、datasets、evaluate、accelerate、sentencepiece——因为 Hugging Face 的课程从第一章就要用。

没构建过也能跑：启动脚本会退回官方科学计算镜像，课程里纯 pandas 与 scikit-learn 的部分照样能用，用到 transformers 的格子会报模块找不到。

容器的挂载与限额：

| 项 | 值 | 理由 |
|---|---|---|
| 课程目录 | `data/user/courses` 只读，容器内路径与宿主完全相同 | 路径一致省掉换算；只读保证学生改不动课程原文 |
| 工作目录 | `data/user/workspace` 可写，路径同上 | 图表等产物落在这里，宿主直接能读 |
| 模型缓存 | `HF_HOME` 指向工作目录下的 `.hf-cache` | 重建容器不用重新下载模型 |
| 内存 | 4 GB | 每个内核 150 到 300 MB，加载数据集后可能到 1 GB 以上 |
| CPU | 2 核 |  |
| 进程数 | 256 |  |
| 运行身份 | uid 1000（非 root），与宿主的用户一致 | 产物文件宿主可读可写 |
| 端口 | 只绑 127.0.0.1:9189 | 局域网访问不到 |

访问口令每次启动重新生成，写进 `~/DeepTutor-ext/.kernel-token`（仅本人可读），不打印、不入日志。

## 故障排查

### 页面上点运行报「内核容器没有应答」

容器没起或挂了。`make kernel-status` 看状态，`make kernel-logs` 看日志，`make kernel-start` 重起。

### 页面上图裂

产物路径没落在 DeepTutor 允许公开访问的白名单里。这个白名单在 `path_service.is_public_output_path`，我们用的是 `workspace/chat/chat/<任务>/code_runs/` 这条规则。地址由实际路径相对数据根推导，不要手工拼——层级不是一眼能猜准的，详见 [03 篇](03-notebook执行.md)。

### 改了扩展代码但没生效

扩展是可编辑安装（`pip install -e`），改文件不会自动重载已经加载进内存的模块。**改完必须 `make restart`。**

### 建知识库失败，错误信息像个安全提示

nltk 的工作目录导入拦截误伤。`make verify` 里有专门一项查它。详见 [05 篇](05-踩坑与决策.md)。

### 代码执行全部失败，错误提到 loopback

Ubuntu 24.04 的 AppArmor 限制了无特权用户命名空间。确认：

```bash
sysctl kernel.apparmor_restrict_unprivileged_userns   # 应该是 0
```

不是 0 就写进 `/etc/sysctl.d/`（这台机器已经写了 `60-apparmor-namespace.conf`）。详见 [05 篇](05-踩坑与决策.md)。

### 服务起不来，日志说端口被占

DeepTutor 会明确报出占端口的进程。**9185 是 novnc 的 websockify，不要动它。** 改 `system.json` 换端口，同时改 `Makefile` 里的 `FRONT_PORT` / `BACK_PORT`。

### 浏览器里组件行为怪异

前端跑的是开发服务器，热更新有时会留下半程状态。先关掉浏览器会话重开，再判断是不是真缺陷。
